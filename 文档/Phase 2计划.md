## 我强烈建议你**只挑 2~3 个**先做，按这个优先级：

### 第一档：先做 **2.2 Telegram 告警**（半天）

理由：
- **立刻产生价值**：你不用每次跑 `check_status.py` 看，热点自动推到手机
- **代码量极小**：几十行 Python + 一个 Telegram Bot Token
- **零新依赖**：HotnessService 算完直接调 Telegram API
- **风险极低**：失败也不影响 hotness 主流程

### 第二档：再做 **2.7 多时间窗口**（1-2 天）

理由：
- 你现在只能看 1h 窗口的"突然爆发"，看不到"持续上升"
- 加 6h 和 24h 窗口的榜单后，**两种热点都能识别**：
  - 1h 突然爆发 → 短线机会
  - 6h 持续上升 → 叙事在发酵
- 改动只在 hotness_service.py 加个循环，不动表结构

### 第三档：然后做 **2.5 LLM 简报**（3-5 天）

理由：
- 这是真正的"质量跃迁"——把"$WIFHAT 排第 1"变成"$WIFHAT 是 Solana 上的 Trump-themed meme，KOL X 推动，过去 1 小时 87 次提及"
- 但是工程量大，需要重新打开 Ollama，且你之前关掉老链路就是为了不调 LLM
- 做之前先把 2.2 和 2.7 跑稳了再开

### 暂时**不做**：2.1 共现 / 2.3+2.4 Embedding 聚类 / 2.6 情绪

理由：
- 2.1 共现网络数据量上来才有意义，你现在每小时才几十次提及，共现关系太稀疏算不出有意义的东西
- 2.3+2.4 Embedding 工程重（要 FAISS / bge-m3 模型 / HDBSCAN），收益不及 2.5 直接调 LLM
- 2.6 情绪分析锦上添花，不是核心需求
